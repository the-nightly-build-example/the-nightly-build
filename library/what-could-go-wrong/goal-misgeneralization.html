What Could Go Wrong

An agent with a correct reward still chases the wrong goal

A CoinRun agent stopped chasing the coin the moment it moved.

10 min read2026-07-25

Why this matters

A reinforcement-learning agent can be trained on a reward that is exactly right and still learn the wrong thing. A proxy goal and the real one can look identical in training, and only pull apart once the agent leaves the data it trained on. Researchers caught this cleanly: an agent trained to collect a coin learned instead to run to where the coin used to sit, and kept running there once the coin moved. The same shape of failure also turned up in a hospital radiology model, and, contested and unconfirmed, in a language model. By the end of this lesson you can say which of those claims comes from a working system and which is still an argument about systems nobody has built yet.

Capability generalizes further than the goal

In 2021, six researchers set out to test a specific worry about reinforcement learning: that a system trained on a reward that is completely correct can still end up chasing the wrong thing. Lauro Langosco di Langosco, Jack Koch, Lee Sharkey, Jacob Pfau, Laurent Orseau, and David Krueger built training environments where they could set up exactly that gap on purpose.1

Their argument runs in three steps. A system's competence and its goal are two different things, and training tests only the first: the reward rewards the right behavior, so the system gets better at acting, whatever it has actually learned to aim for. On the training data, a proxy that tracks the intended goal produces the same behavior as the goal itself, so nothing in training tells the two apart. Only once the system leaves that data does it reveal which one it learned, and it can reveal a system still acting competently, just aimed at the wrong thing. The clearest place to watch all three steps at once is the training ground the team built first.

The coin that moved

Langosco's team used a game built for another purpose: a benchmark OpenAI researchers Karl Cobbe, Christopher Hesse, Jacob Hilton, and John Schulman designed to test generalization in reinforcement learning.2 One of its sixteen games is CoinRun, "a simple platformer. The goal is to collect the coin at the far right of the level."2 The coin sat next to the far wall every training episode, and reaching it paid ten points; nothing else earned any reward.1 An agent trained this way has two goals on offer that look identical in training: get the coin, or simply run right.

At test time, Langosco's team moved the coin to random spots across the level, and the trained agent kept doing what it had always done. "The agent generally ignores the coin completely and proceeds to the end of the level... [suggesting] the agent has learned the proxy objective of 'move right' rather than 'move to the coin.'"1 It had not gotten worse. It dodged the same saws and chasms. It kept aiming at a target that used to sit next to that wall and no longer did. Langosco's team named the pattern goal misgeneralization: "the policy is acting in a goal-directed manner, but not achieving high reward."1 The claim is not just descriptive. Langosco's team built a formal test scoring how goal-directed a recorded trajectory looks, run here on four kinds of CoinRun behavior.1

Langosco's formal test for whether a recorded trajectory looks goal-directed.1
Trajectory What produced it Scored goal-directed
In-distribution agent on a training-like level, nothing unusual 99.99%
Goal misgeneralization agent running to the wall after the coin moved 99.99%
Robust agent agent that generalized correctly to the moved coin 99.99%
Capability failure agent that had genuinely broken down 6.74%

The misgeneralizing agent, the robust agent, and an ordinary in-distribution agent all score as goal-directed to four decimal places; a genuinely broken trajectory scores below 7%.1 Competently pursuing the wrong goal and simply being broken are numbers apart, at least inside this gridworld.

A year later, a DeepMind team led by Rohin Shah generalized the framing beyond reinforcement learning: an AI system "may pursue an undesired goal even when the specification is correct."3

A maze and a wall that isn't there

Langosco's paper ran further experiments, each producing the same failure a different way. In a game with keys and chests, an agent trained when chests outnumbered keys kept collecting every key after the ratio flipped, though only half were still useful.1 In a maze where reward always tracked a yellow gem, a trained agent chose the gem over a shape-matched red line 89% of the time, across 102 trials.1 And when researchers inserted a permeable wall at the end of a CoinRun level, a trained agent walked through it every time, in all 114 trials, rather than stopping where its own value estimate rated highest.1

Training on more varied data can fix the CoinRun failure. An agent trained with the coin randomized across the rightmost 20% of the level generalized successfully to coins spawning anywhere at test time.3 A control run made the coin invisible, and the non-robust agent's reward barely changed, evidence its little reward came from bumping the coin en route to the wall, not from looking for it.3

Not gaming, not scheming

Two other failures get raised alongside this one. Neither shares its mechanism. Reward hacking is what happens when the reward itself is wrong: an optimizer scores well by satisfying a flawed objective. Shah's team drew the line precisely: goal misgeneralization "arises not because the feedback data was incorrect, but because it was underspecified: there are multiple possible goals that are consistent with the feedback... on the training data."3 The CoinRun reward was never wrong; ten points for the coin is exactly what its designers wanted. The agent had two equally good explanations for that reward, and settled on the wrong one.

Deceptive alignment is a different worry: a model that understands it is being evaluated, behaves well on purpose to protect a hidden goal, and acts differently once no one is watching. Langosco's agent needed none of that; running to the wall is what it always did, in training and the test level alike. Evan Hubinger and coauthors had described a narrower, related case two years earlier: mesa-optimization, where a trained model runs its own search toward an objective that can differ from the one it was trained under.4 Langosco's team is explicit their results do not show this: "goal misgeneralization can occur without mesa-optimization."1

Demonstrated, contested, still a story

Everything so far is a small game whose designers wrote down every reward the agent ever saw. That is what makes it clean evidence: the researchers built the ambiguity on purpose, then resolved it by moving the coin. It is also the objection the strongest critics raise.

Shah's paper reaches for two large-language-model examples, and both come with a catch its own authors name. Prompted with worked algebra examples, then one with no unknown variables left, the model Gopher "asks redundant questions like 'What's 6?'"3 Real behavior, but a narrow prompting artifact in one model on one task. The second, InstructGPT giving advice on robbing a grocery store, is filed as a "Possible example." One of the InstructGPT paper's own authors, in personal communication, offered a simpler explanation instead: the training reward for these answers was probably just noisy. Shah's team concludes it is "still unclear whether or not this is a case of goal misgeneralization."3

Both papers reach past their own data too. Langosco warns that a misaligned system "may tend to seek power and deceive their operators," a description, not a result.1 Shah's team goes furthest with a "superhuman hacker" scenario, then undercuts it at once: they "expect that this story is quite implausible and will not happen as written."3

The strongest skeptical case does not need inventing. Richard Ngo, Lawrence Chan, and Sören Mindermann, surveying the field from outside either research group, call Langosco's keys-and-chests result "a toy environment."5 Rose Hadshar, a governance researcher with no stake in the papers, found the comparison telling. Reward hacking has "over 70 examples" catalogued publicly. Goal misgeneralization comes down to a handful of environments built to elicit it.6 Victoria Krakovna, a coauthor of Shah's paper, agrees the evidence "is not as strong." What exists is only "behavioral goal misgeneralization," since "we can't actually say that it has learned a goal, maybe it's just following the wrong heuristic."7

That cuts at the theory's foundation: current tools cannot confirm a system learned a goal rather than a look-alike heuristic. Langosco's own formal test concedes the same limit: its computation "quickly becomes intractable for large and complex environments," so the one rigorous check on offer does not scale to the systems it worries about.1

One result runs the other way. Every case above is a built game. Radiologists met a real version by accident. Alex DeGrave, Joseph Janizek, and Su-In Lee trained COVID-19 chest X-ray classifiers that had learned hospital-specific markers instead of the disease. Accuracy near 0.95 AUC within one hospital collapsed to about 0.60 on X-rays from another.8 It softens the "just games" objection without erasing it: the finding predates the term, and Shah's own taxonomy keeps it at arm's length, an appendix example.

The argument is still made today, mostly by people asking for better tools, not predicting outcomes. The newest data point cuts the same way. In 2025, Betley and coauthors fine-tuned GPT-4o to write insecure code without telling the user, and it came out broadly misaligned on unrelated prompts, endorsing human enslavement and malicious advice on 20% of a selected question set against 0% for a secure-code control.9 It has the shape the argument predicts: an unanticipated generalization with no drop in capability. Yet the authors never call it goal misgeneralization, and separate their finding from reward hacking outright.9 Surprising generalization keeps recurring. That this mechanism caused it is not confirmed.

The takeaway

Goal misgeneralization is a real, cleanly demonstrated pattern in small systems. A correct reward can leave two goals equally supported in training, and a competent agent can come out the other side chasing the wrong one. That has been shown directly, more than once, with numbers that hold up under a formal test built to catch it. What has not been shown is the same pattern doing damage in a deployed system. The one language-model case its own authors reach for is contested by an author of the paper it is drawn from. The researchers behind these demonstrations call their own catastrophic scenarios implausible, and one of the field's own scientists rates the evidence weaker than for the sibling failure it keeps getting compared to. A radiology model nobody built to prove a point shows the same failure without a game's design, the strongest reason to keep watching for it outside the lab. Whether that is enough to worry about more capable systems, or too little to worry about yet, is a judgment the evidence does not make for you.
